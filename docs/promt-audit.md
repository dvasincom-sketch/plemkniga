# Промт для нового чата: полный аудит проекта

Скопировать целиком в первое сообщение нового чата.

---

Ты работаешь над проектом «Племенная книга» — он лежит в `~/plemkniga`.
Прежде чем что-либо делать, прочитай `docs/reshenya.md` целиком: это
журнал решений, и почти на всякий вопрос «почему так» ответ уже там.

## Что это за система

Информационная система племенного учёта крупного рогатого скота.
Next.js 16, Payload CMS 3, PostgreSQL, TypeScript. Три домена на одной
сборке, различаются заголовком `Host` (`lib/hosts.ts`, `lib/tenant.ts`):

- `plem.online` — витрина продукта, шесть языков (ru, en, kk, hy, be, ky);
- `holstein.plem.online` — живая племенная книга голштинской ассоциации;
- `demo.plem.online` — показательная книга, ещё не развёрнута.

Система обязана отдавать данные в государственный реестр ФГИАС ПР
(двадцать шаблонов) и следует руководствам ICAR; обмен — по стандарту
ICAR ADE.

## Как мы работаем — правила, которые не обсуждаются

**Ты правишь файлы, но не коммитишь и не пушишь.** В конце работы даёшь
одну команду `git add -A && git commit -m … -m …` для вставки в терминал.
Причина: git через мост оставляет `.git/*.lock`.

**Комментарии объясняют «почему», а не «как».** Отвергнутый вариант
и причина отказа ценнее описания работающего кода. Прозой, без списков
внутри абзацев. Комментарии русские.

**Каждое спорное решение — своей записью в `docs/reshenya.md`:**
заголовок, рассуждение, чем плохи отвергнутые варианты, и строка
«Где смотреть» с путями.

**Проверка на живых данных. «Собирается» — не проверка.** Минимум:
`npx tsc --noEmit`, `npm run build`, и прогон по настоящей базе. Новая
работа приходит со своим прогоном.

**Ограничения песочницы:** `npm run build` и `npx tsx` в ней не работают
(node_modules собраны под macOS — нет SWC и esbuild). Работают
`npx tsc --noEmit` и обычный `node`. Прогоны запускает человек у себя.

**Известные грабли:**
`'use server'` разрешает только асинхронный экспорт; обратные кавычки
ломают шаблонные строки SQL; `.catch(() => [])` превращает поломку
в тихую неправду; `NEXT_PUBLIC_*` подставляется на сборке; **проверка,
спотыкающаяся о собственный комментарий, наведена не туда**; числа,
не сдвинувшиеся после починки, означают, что починка ушла не туда.

После правки коллекций Payload напомни перезапустить `next dev`; после
`git pull` — `npm run db:sync`.

**Стиль:** без точек с запятой, одинарные кавычки, ширина 100. Prettier
не настроен, его умолчания проекту противоречат. Типографика по
«Справочнику издателя и автора» Мильчина и Чельцовой: кавычки-ёлочки,
тире, десятичная запятая. Неразрывных пробелов в файлах данных нет,
NBSP ставится только в разметке.

## Устройство, которое надо знать до правок

**Реестры данных — источник правды, а не копия.** `lib/checks-registry.ts`
(55 зоотехнических правил), `lib/check-registry.ts` (перечень прогонов
кода — не путать), `lib/notes.ts` (11 разборов), `lib/terms.ts` +
`lib/terms/` (83 термина словаря), `lib/studies.ts` (исследования),
`lib/fgias-pages.ts` + `lib/fgias/` (20 страниц шаблонов реестра),
`lib/breed-pages.ts`, `lib/fgias-templates.ts`, `lib/breeding-index.ts`
(`TRAIT_BASE` — 11 признаков с σ и наследуемостью), `lib/compliance.ts`,
`lib/icar-map.ts`, `lib/ade-schema-map.ts`.

**Переводы устроены тремя механизмами**, и путать их нельзя:
короткие подписи — `Record<Locale, …>` (язык забыть нельзя);
длинные тексты страниц — `Translated<T>` с явным откатом и оговоркой
(`lib/i18n/translated.ts`, `noticeFor`); данные под страницами —
словари по языкам в `lib/i18n/data/` (`pickText`, `lib/i18n/data-text.ts`).
Разборы, словарь, исследования, страницы пород и шаблонов — **русские
намеренно** и переводиться не будут.

**Числа на страницах считаются из кода, а не набираются словами.** Это
правило нарушалось несколько раз, и каждый раз страница врала месяцами.

**Связь словаря со страницами объявляет одна сторона**: разбор,
исследование и страница породы перечисляют `terms`, обратное направление
считается (`lib/term-links.ts`).

## Сорок с лишним прогонов

## Что уже находили — классы ошибок, которые здесь водятся

Аудит стоит вести с этим списком под рукой: все они были найдены
не сборкой и не типами, а чтением и открыванием страниц.

1. **Число, набранное словом.** «Отдача семи коллекций» при одиннадцати;
   «пятнадцать пробелов» при шестнадцати. Живёт годами.
2. **Подпись обещает не то, что делает поле.** Сервис-период на экране
   считался до первого осеменения, а в реестр уходил до плодотворного —
   одна книга показывала и отдавала разные числа под одним именем.
3. **Одно слово над разными величинами.** «Достоверность» стояла над
   семью полями с четырьмя разными шкалами.
4. **Обещание, опережающее реализацию.** Витрина писала, что лактация
   за 305 дней вычисляется из доений; расчёта в коде нет.
5. **Чужое число вместо своего.** σ смертности приплода взято от
   живучести коров — то есть измерено на других животных.
6. **Проглоченная ошибка.** `catch`, печатающий придуманное объяснение
   вместо настоящей причины.
7. **Свойство в `style`, отменяющее отзывчивость** — молча и наполовину.
8. **Маршрут, падающий на боевом сервере при зелёной сборке**
   (`generateStaticParams` без всех изменяемых кусков адреса).
9. **Ссылка, ведущая в «не найдено»,** выглядящая рабочей на странице.
10. **Проверка, которая ничего не проверила и ответила зелёным**
    (`fetch` в Node выбрасывает заголовок `Host`).

## Что от тебя нужно сейчас

**Полный аудит проекта — каждая строчка кода и текста.** Ищи прежде
всего тихую неправду: места, где система говорит одно, а делает другое,
и где заметить это нельзя ни глазами, ни сборкой, ни типами.

По каждой находке скажи: **что именно неверно, чем это опасно, как это
заметить и во что обойдётся починка.** Не чини всё подряд — сперва
перечисли и дай мне выбрать порядок.

Отдельно ищи:

- расхождение текста на витрине с тем, что делает код;
- числа, названные словом там, где их можно посчитать;
- расчёты одной величины в двух местах без сверки между ними;
- поля, чья подпись обещает не то, что принимает валидация;
- проверки, которые не могут упасть, и проверки, наведённые не туда;
- страницы, на которые не ведёт ни одна ссылка изнутри;
- места, где отсутствие данных выдаётся за отрицательный результат.

Работай большими независимыми кусками, используй подагентов на разбор
разных частей дерева — оно большое (`src/collections`, `src/lib`,
`src/app`, `src/scripts`, `docs`).
