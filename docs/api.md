# API

Что доступно сейчас и какие интеграционные контракты спроектированы.

Статусы: ● работает · ◐ спроектировано · ○ план.

## 1. Текущий API ●

Payload CMS поднимает REST и GraphQL поверх модели данных автоматически.
Права доступа те же, что и в интерфейсе, но привычная формула «аноним видит
публичное, пользователь — своё хозяйство» верна только для `animals`.
У остальных коллекций правила проще и шире — см. таблицу ниже.

### Аутентификация

```http
POST /api/users/login
Content-Type: application/json

{ "email": "farmer@nazarovskoe.ru", "password": "plemkniga123" }
```

Ответ содержит JWT и устанавливает cookie `payload-token`. Дальше запросы
авторизуются либо этой cookie, либо заголовком:

```http
Authorization: JWT <token>
```

Текущий пользователь — `GET /api/users/me`.

### Коллекции

| Ресурс | Что содержит |
| --- | --- |
| `/api/animals` | животные: идентификация, оценка, фенотип, происхождение, генетика, движение |
| `/api/organizations` | хозяйства и сервисные организации |
| `/api/herds` | стада |
| `/api/calvings` | отёлы и межотельный цикл |
| `/api/inseminations` | осеменения |
| `/api/milk-tests` | контрольные дойки |
| `/api/health-events` | события здоровья |
| `/api/events` | лента событий животного |
| `/api/documents` | документы, привязанные к животному или организации |
| `/api/data-submissions` | пакеты загрузки данных и их история |
| `/api/access-requests` | запросы доступа к закрытым карточкам и решения по ним |
| `/api/users` | учётные записи |
| `/api/media` | файлы |
| `/api/breeds`, `/api/lines`, … | справочники НСИ |

### Права на чтение по коллекциям

| Коллекция | Правило чтения | Что это значит на практике |
| --- | --- | --- |
| `animals` | `animalRead` | аноним — только `publicVisible = true`; авторизованный — свою организацию плюс публичные записи; администратор — всё |
| `organizations`, `herds`, `media` | `anyone` | читает кто угодно, включая анонима: названия хозяйств и стад выводятся в публичной таблице |
| `calvings`, `inseminations`, `milk-tests`, `health-events`, `events`, `documents`, `data-submissions` | `isAuthenticated` | любой авторизованный читает записи **всех** хозяйств, не только своего |
| `access-requests` | `accessRequestRead` | заявитель, владелец животного, администратор |
| `users` | `selfOrAdmin` | сам себя либо администратор |
| справочники НСИ | `anyone` | читает кто угодно |

Строка про фенотип и события — не описка, а состояние кода: ограничение
чтения по организации сделано только для животных. Через `/api/milk-tests`
или `/api/calvings` авторизованный пользователь получает первичные данные
чужих хозяйств, хотя карточка животного может быть от него закрыта. Для
публичной книги это несоответствие, и закрывать его нужно в правилах доступа
самих коллекций, а не в интерфейсе.

Создание и изменение требуют авторизации — кроме `users` и `organizations`,
где создание открыто всем: на них держится форма регистрации. Справочники НСИ
изменяет только администратор. **Удаление в любой коллекции доступно только
администратору Ассоциации** (`isAdmin`).

### Чтение

```http
GET /api/animals?where[kind][equals]=bull&where[ipc][greater_than]=1000
                &sort=-ipc&limit=25&page=1&depth=1
```

Поддерживаются операторы `equals`, `not_equals`, `greater_than`,
`less_than`, `in`, `contains`, `exists`, логические `and` / `or`,
а также `depth` — глубина разворачивания связей (например, чтобы вместе
с животным пришли объекты отца и матери, а не только их идентификаторы).

**О сортировке по убыванию.** `sort=-ipc` формально работает, но первыми
придут записи без оценки: PostgreSQL при `ORDER BY … DESC` ставит NULL
в начало. Поэтому само приложение сортирует по служебным полям `-ipcRank`
и `-summary.milkRank`, где пустое значение заменено на −1 000 000. Для выдачи
«сначала лучшие» через API следует использовать их же.

**Об архиве.** Служебные записи предков (`archived = true`) исключаются только
на страницах приложения. REST и GraphQL возвращают их наравне с остальными;
если они не нужны, условие приходится задавать в запросе явно.

Ответ:

```json
{
  "docs": [ { "id": 2493, "identNumber": "20197", "name": "Пастила", "...": "..." } ],
  "totalDocs": 132,
  "limit": 25,
  "page": 1,
  "totalPages": 6,
  "hasNextPage": true
}
```

### Запись

```http
POST   /api/animals          создание
PATCH  /api/animals/:id      изменение
DELETE /api/animals/:id      удаление
```

При записи срабатывают те же серверные проверки, что и в интерфейсе: формат
индивидуального номера, запрет на животное в роли собственного родителя,
дата рождения не в будущем, контроль порядка дат рождения (только когда
затронуты дата или связи с родителями), транслитерация клички.

Коэффициент инбридинга при записи **не пересчитывается**. Он считается на лету
`analyzeAncestry` — при отрисовке вкладки «Происхождение» и при выпуске
документа. Хуки записи делают другое:

| Хук делает | Поле |
| --- | --- |
| присваивает GUID при создании | `uuid` |
| подставляет автора по сессии при создании | `author` |
| пишет, кто и когда изменил | `lastEditUser`, `lastEditTime` |
| считает сумму жира и белка | `summary.fatProteinSum` |
| заполняет служебные ранги сортировки | `ipcRank`, `summary.milkRank` |
| ставит флаг при инбридинге выше 25% | `inbreedingNeedsApproval` |
| каскадно удаляет запросы доступа при удалении животного | `access-requests` |

Флаг `inbreedingNeedsApproval` выставляется по значению поля `inbreeding`,
пришедшему в запросе или уже сохранённому, — не по расчёту по дереву.

### GraphQL

`POST /api/graphql` — та же модель и те же права:

```graphql
query {
  Animals(where: { kind: { equals: bull } }, sort: "-ipc", limit: 10) {
    docs { id identNumber name ipc trustLevel father { identNumber } }
  }
}
```

### Собственные эндпоинты

| Маршрут | Назначение |
| --- | --- |
| `GET /animals/:id/certificate/:kind` | печатная форма документа: `zootechnical` — зоотехнический сертификат, `pedigree` — племенное свидетельство |
| `GET /account/notifications` | лента уведомлений и решения по входящим запросам доступа |
| `GET /account/import` | загрузка CSV с животными |
| `GET /account/export?format=csv\|json` | выгрузка животных своей организации, до 5000 записей |
| `GET /analytics` | сводная аналитика по книге |
| `GET /auctions` | витрина животных, выставленных на продажу |
| `GET /privacy` | политика обработки персональных данных |
| `GET /healthz` | состояние базы, видимые переменные окружения, подсказки |
| `GET /healthz/live` | liveness-проба для Docker, базы не касается, всегда 200 |

`/healthz` всегда отвечает HTTP 200, а результат выражает полем `status`
в теле: `"ok"` либо `"error"` с описанием причины. Это сделано намеренно.
Проба задумана как средство диагностики, и именно в момент, когда база
недоступна, ответ нужнее всего — а платформы и панели нередко прячут тело
ответа с кодом 5xx, показывая вместо него собственную заглушку. Для
автоматической проверки живости контейнера есть отдельный `/healthz/live`;
Docker HEALTHCHECK ходит туда, чтобы неверная строка подключения
не превращалась в «Deploy failed».

### Что идёт мимо REST

Часть операций выполняется не через API коллекций, а серверными действиями
Next (`src/actions/`). Внешнему клиенту они недоступны — это формы приложения.

| Действие | Файл | Что делает |
| --- | --- | --- |
| Запрос доступа | `actions/access.ts` | создаёт `access-request`, отсекая повторный запрос по тому же животному |
| Решение по запросу | `actions/access.ts` | меняет статус и при одобрении переключает животное в `publicVisible / publicDetails = true` |
| Отметка «ленту посмотрели» | `actions/access.ts` | пишет `notifySeenAt` в обход правил доступа |
| Видимость стада | `actions/account.ts` | массово переключает флаги публичности у всех животных организации |
| Импорт CSV | `actions/data.ts` | разбирает файл и создаёт либо обновляет животных по `Инд.№` |
| Публикация пакета | `actions/submissions.ts` | переводит пакет в `accepted` и поднимает уровень достоверности животных |
| Вход и регистрация | `actions/auth.ts` | логин, создание пользователя и организации, выход |

Разделение практическое: эти операции затрагивают несколько коллекций сразу
и требуют собственных проверок, которые в правах доступа одной коллекции
не выражаются.

## 2. Приём фенотипа в форме ICAR ADE ◐

Целевой контракт интеграционного слоя — открытый JSON-стандарт ICAR ADE
(репозиторий `adewg/ICAR`, OpenAPI 3.1, JSON Schema 2020-12). Собственный
формат обмена пришлось бы объяснять каждому партнёру отдельно; ADE уже
реализован UNIFORM-Agri, а Section 2 ICAR Guidelines прямо отсылает к нему
для данных доения.

Планируемая группа эндпоинтов:

```http
POST /api/ade/milk-recording      результаты контрольной дойки
POST /api/ade/reproduction        осеменения, стельности, отёлы
POST /api/ade/animal-events       перемещения, выбытия
GET  /api/ade/animals             выдача животных наружу в форме ADE
```

Принципы обработки:

- **идемпотентность** — повторная отправка того же события не создаёт дубль;
  ключ — идентификатор животного плюс тип события плюс дата;
- **частичный приём** — строки, не прошедшие проверку, отклоняются
  индивидуально, остальные принимаются; это принципиальное отличие
  от текущей логики пакетов, где отклоняется весь пакет;
- **прослеживаемость** — каждая принятая запись хранит источник:
  система-отправитель, идентификатор пакета, время приёма.

## 3. Приём генотипов ◐

Файлы с чипов слишком велики для синхронного разбора, поэтому обработка
асинхронная.

```http
POST /api/genotypes/upload
Content-Type: multipart/form-data

file=@herd_2026.vcf
chip=GGP Bovine 150K
assembly=ARS-UCD1.2
alleleCoding=TOP
laboratory=<id>
```

Ответ — идентификатор задания. Статус и протокол контроля качества:

```http
GET /api/genotypes/jobs/:id
```

```json
{
  "status": "completed",
  "samples":  { "total": 480, "accepted": 471, "rejected": 9 },
  "markers":  { "total": 138421, "accepted": 134980, "rejected": 3441 },
  "rejections": [
    { "reason": "call rate образца ниже 0.90", "count": 7 },
    { "reason": "менделевский конфликт с заявленным отцом", "count": 2 }
  ],
  "protocolUrl": "/api/media/..."
}
```

Обязательные метаданные — чип, сборка генома и конвенция кодирования аллелей.
Без них файл принять нельзя: смешивание конвенций даёт тихую порчу данных,
которая проявится только падением точности оценки. Подробности —
в [genomnyy-konveyer.md](genomnyy-konveyer.md).

## 4. Коннекторы к системам управления стадом ○

Публичного REST API нет ни у DairyComp 305, ни у DelPro, ни у AfiFarm.
Поэтому это не «интеграция по API», а набор адаптеров с общим внутренним
контрактом.

| Система | Механизм забора | Что учесть |
| --- | --- | --- |
| DairyComp 305 | периодический прогон командной строки (`LIST`, `EVENTS`, `BREDSUM`) и разбор выгрузок | передача данных третьей стороне оформляется VAS Data Release Agreement; подписывает ферма |
| DelPro | партнёрская интеграция либо чтение резервных копий БД | схема БД официально не опубликована; такой путь требует договорённости с вендором или фермой |
| UNIFORM-Agri | ICAR ADE | самый прямой путь, стандарт уже реализован вендором |
| AfiFarm | по договорённости с вендором | публичной спецификации найти не удалось |

Внутренний контракт адаптера одинаков для всех: адаптер обязан вернуть события
в форме ADE и указать источник. Тогда добавление новой системы управления
стадом не затрагивает ядро.

## 5. Государственные реестры ○

**ВетИС «Хорриот»** — реализуемо. Шлюз ВетИС.API, сервис
`ApplicationManagementService`, схемы на `api.vetrf.ru/schema/platform/services/`.
Доступ по официальному письму во ФГБУ «ВНИИЗЖ», сначала тестовый контур,
апробация не менее 10 рабочих дней. Сроки предсказуемы.

**ФГИАС ПР** — заблокировано отсутствием спецификаций. Регистрация обязательна
с 01.03.2026, но публичного описания форматов обмена и API в открытом доступе
нет. Ставить конкретный срок в план нельзя, пока спецификации не получены;
разумный шаг — запрос через Ассоциацию как отраслевое объединение.

Правовые детали обоих реестров — в [standarty.md](standarty.md).

## 6. Публичная проверка свидетельства ○

```http
GET /verify/:certificateNumber
```

Страница без авторизации: показывает, что свидетельство с таким номером выдано,
кем и когда, на какое животное, и действует ли оно сейчас. Ссылка кодируется
в QR на бланке. Показываются только данные из снимка на момент выдачи —
свидетельство не должно меняться задним числом при пересчёте оценок.

Подробнее о требованиях к сертификатам — [sertifikaty-audit.md](sertifikaty-audit.md).
