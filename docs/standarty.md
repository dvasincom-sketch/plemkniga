# Стандарты и соответствие требованиям

Какие отраслевые и государственные требования мы обязаны учитывать, что
из них уже отражено в модели данных и что предстоит сделать.

Статусы: ● работает · ◐ спроектировано · ○ план.

---

## 1. ICAR

International Committee for Animal Recording — отраслевой орган, чьи Guidelines
де-факто определяют, как в мире ведут учёт продуктивности. Руководство издаётся
отдельными разделами (Sections); ниже — те, что нас касаются.

### Section 2 — Cattle Milk Recording (версия июнь 2023) ◐

Правила контрольных доек:

- **стандартная лактация** — от отёла до запуска либо до 305-го дня,
  если лактация длиннее;
- **референсный метод** — четырёхнедельный интервал между контролями;
- минимум **11 контролей в год**, допустимый интервал между ними — **22–37 дней**.

**Расчёт накопленного удоя.** Основной метод ICAR — Test Interval Method (TIM):

```
MY = I₀·M₁ + Σ_{i=1..n−1} Iᵢ·(Mᵢ + Mᵢ₊₁)/2 + Iₙ·Mₙ
```

где Mᵢ — суточный удой на i-м контроле, Iᵢ — интервал между контролями в днях,
I₀ — от отёла до первого контроля, Iₙ — от последнего контроля до конца лактации.
По сути это трапецеидальное интегрирование кривой лактации по точкам контроля.

Есть также Centering Date Method, Best Prediction и Multiple-Trait Procedure —
последний прогнозирует 305-дневные удой, жир, белок и SCS через функцию Wilmink
с фиксированным k = 0,05.

**Что это значит для системы.** Поле «удой за 305 дней» в лактации ● уже есть,
но сейчас оно принимается как данность из импорта. Правильно — считать его
самим по контрольным дойкам методом TIM и хранить рядом с методом расчёта.
Тогда значение воспроизводимо и его можно защитить перед проверяющим.

### Модели лактационных кривых ◐

| Модель | Формула | Когда применяют |
| --- | --- | --- |
| **Wood** (1967), неполная гамма-функция | y_t = a · t^b · e^(−c·t) | классическая нелинейная форма для целых лактаций; параметры интерпретируются биологически — уровень после отёла, подъём к пику, спад. Удобна, когда нужно объяснить зоотехнику форму кривой |
| **Wilmink** (1987) | y_t = a + b · e^(−k·t) + c · t | компромисс, хорошо описывает раннюю фазу; k обычно фиксируется (в процедурах ICAR k = 0,05). Стандарт для test-day и random regression моделей |
| **Ali–Schaeffer** (1987) | y_t = a + b·X + c·X² + d·ln(1/X) + e·[ln(1/X)]², где X = t/305 | линейна по параметрам, поэтому подставляется как подмодель в test-day модели генетической оценки; гибче ведёт себя на краях лактации |

Практический выбор для продукта: **Wood** — для показа кривой в карточке
животного и расчёта персистентности, **Ali–Schaeffer** — как подмодель
в будущей генетической оценке по контрольным дойкам.

### Section 4 — DNA Technology ◐

Проверка происхождения по SNP. Здесь важное уточнение, потому что в отрасли
часто цитируют пороги в виде абсолютного числа несовпадений — **ICAR задаёт
их в процентах конфликтующих маркеров**.

Панели:

- **ISAG** — 200 SNP (100 Core + 100 Additional);
- для поиска родителей (parentage discovery) ICAR рекомендует **ICAR554** —
  554 SNP, с требованием не менее 500 маркеров с MAF > 20% и call rate > 90%.

Пороги:

| Задача | Правило |
| --- | --- |
| Верификация заявленного родителя (панель до 200 SNP) | родитель подтверждается, если конфликтуют **менее 1%** генотипов «потомок–родитель». Конфликт — противоположные гомозиготы |
| Проверка заявленной пары родителей | если **более 1%** маркеров у отца и матери гомозиготны по одному и тому же аллелю, заявленное спаривание отклоняется |
| Поиск родителя (панель от 500 SNP) | менее **0,5%** конфликтов — принимается; более **1,5%** — отклоняется; **0,5–1,5%** — серая зона, требующая перепроверки по всем доступным маркерам |
| Контроль качества | исключать SNP с call rate < 90%; аннулировать генотип особи при общем call rate < 90% |

**Как это соотносится с таблицами в абсолютных числах.** Отдельное руководство
ICAR по проверке происхождения (GenoEx) приводит пороги в виде количества
конфликтующих маркеров: для одного родителя 0–2 — Accepted, 3–5 — Doubtful,
больше 5 — Excluded. Противоречия с процентным правилом здесь нет: 1% от панели
в 200 SNP — это как раз 2 маркера. Тот же документ задаёт набор статусов
`NOT CHECKED`, `LOW CALL`, `ACCEPTED`, `DOUBTFUL`, `EXCLUDED`.

Значение статуса **DOUBTFUL** для продукта отдельное: это ровно та ситуация,
ради которой существует ручной разбор. Бинарное «подтверждено / отклонено»
её не выражает.

**Что это значит для системы.** В модели данных ◐ нужно заменить свободный
текстовый результат ДНК-теста на структурированный: отдельно вердикт по отцу,
отдельно по матери, значения — `ACCEPTED` / `DOUBTFUL` / `EXCLUDED` /
`LOW CALL` / `NOT CHECKED`, плюс доля конфликтующих маркеров и номер теста.
Именно это печатается в зоотехническом сертификате как «Отец +, Мать +».

### Section 10 и ISO 11784/11785 ◐

Электронная идентификация: ICAR сертифицирует RFID-транспондеры, считыватели
и обычные пластиковые бирки. ISO 11784 определяет структуру кода,
ISO 11785 — технический принцип обмена.

В модели данных поля `earTag`, `chipNumber`, `chipDate`, `isoId` ● уже есть.

### Section 15 и ICAR ADE — обмен данными ◐

Два поколения стандарта:

- **Легаси** (Section 15, редакция февраль 2019) — Animal Data Exchange
  на основе SOA: XML-схемы и SOAP/WSDL, процедуры Methodology, Milking Data,
  Animal Data, Reproduction Data, Technical Data.
- **Актуальное** — открытый JSON-стандарт в репозитории
  [adewg/ICAR](https://github.com/adewg/ICAR) под Apache 2.0: JSON Schema
  типов ресурсов, OpenAPI для location-centric API и generic data exchange API.
  Релиз 1.5.1 от 10.12.2025, база — OpenAPI 3.1 и JSON Schema 2020-12.

**Наше решение:** целевым контрактом интеграционного слоя берём современный
ICAR ADE. Причины прагматичные — он открыт, развивается, уже реализован
UNIFORM-Agri, и Section 2 прямо отсылает к нему для данных доения с роботов.
Собственный формат обмена пришлось бы объяснять каждому партнёру отдельно.

### Section 8 — ICAR Certificate of Quality ○

Знак качества для организаций-членов ICAR, охватывающий 16 областей
деятельности: идентификация, учёт продуктивности, ведение племенной книги,
обработка данных, лабораторный анализ, генетическая оценка. Выдаётся на 5 лет
с обязательным консультативным пересмотром через 30 месяцев; процедура включает
анкету и выездной аудит.

Для Ассоциации это долгосрочный ориентир: сертификат подтверждает, что
племенная книга ведётся по международным правилам, и это прямой аргумент
при экспорте племенного материала. Для нас как для системы — набор требований
к прослеживаемости и воспроизводимости расчётов, которые дешевле заложить
сразу, чем внедрять потом.

## 2. Регламент (ЕС) 2016/1012 ◐

Форма зоотехнического сертификата для торговли чистопородными племенными
животными. Бланк содержит 15 нумерованных разделов; присланный Ассоциацией
образец разобран по полям в [sertifikaty-audit.md](sertifikaty-audit.md).

Ключевое, чего не хватает модели данных: раздел племенной книги (А / Б),
номер в племенной книге отдельно от индивидуального, страна рождения,
селекционер отдельно от владельца, способ получения потомка (ЕТ),
структурированный результат теста происхождения.

## 3. Российские государственные требования

### ФГИАС ПР — племенные ресурсы ○

Официальное название — **федеральная государственная информационно-аналитическая
система племенных ресурсов**. В отрасли её часто называют ФГИС «Племя»,
но в нормативных актах этот вариант не используется.

| Что | Детали |
| --- | --- |
| Правовая база | ФЗ от 04.08.2023 № 454-ФЗ (изменения в закон «О племенном животноводстве») |
| Положение о системе | ПП РФ от 01.11.2025 № 1741 |
| Правила регистрации | ПП РФ от 01.11.2025 № 1742 |
| Оператор | Минсельхоз России |
| Срок действия актов | с **01.03.2026** по **01.03.2032** |
| Обязательность | с 01.03.2026 регистрация племенных животных и стад обязательна; животное вне системы нельзя продать как племенное |
| Кто регистрирует | органы исполнительной власти субъектов РФ в сфере племенного животноводства; сведения подают сами хозяйства |
| Охват | 13 видов племенных животных, все регионы |

**Техническое ограничение, о котором надо знать.** Перечни передаваемых
сведений содержатся в приложениях к ПП № 1742, а формы и форматы устанавливает
Положение — но **публичной технической спецификации, XSD-схем или описания API
в открытом доступе найти не удалось**. Требований по аккредитации сторонних
информационных систем для ФГИАС ПР также не обнаружено.

Практический вывод: интеграцию с ФГИАС ПР нельзя ставить в план с конкретным
сроком, пока не получены спецификации. Разумный шаг — запрос в Минсельхоз
или через Ассоциацию как отраслевое объединение. До этого модель данных
готовится к передаче: GUID животного ● уже присваивается автоматически
и не зависит от внутрихозяйственного номера.

### ВетИС и «Хорриот» — маркирование и учёт ○

Здесь ситуация противоположная: шлюз для сторонних систем существует и работает.

| Что | Детали |
| --- | --- |
| Правовая база | ФЗ от 28.06.2022 № 221-ФЗ |
| Правила учёта | ПП РФ от 05.04.2023 № 550 |
| Ветеринарные правила маркирования | приказ Минсельхоза от 03.11.2023 № 832 |
| Оператор | Россельхознадзор, компонент «Хорриот» ФГИС «ВетИС» |
| Обязанность маркирования | с 01.03.2024 |
| КРС | только **индивидуальное** маркирование; постановка на учёт — до 01.09.2024, для всех форм хозяйствования |

**УНСМ** — уникальный номер средства маркирования. Формируется автоматически
системой ВетИС по заявке производителя средств маркирования или маркирующего
лица. Начинается с «RU», следующий символ — 1 для индивидуального маркирования,
2 для группового.

Важное различие, которое часто путают: **УНСМ — это не номер животного**.
Номер животного присваивается при регистрации в «Хорриоте» и на бирку
не наносится. В модели данных это два разных поля.

**Порядок подключения сторонней системы:**

1. Обмен идёт через шлюз **ВетИС.API**, сервис `ApplicationManagementService`
   работает с «Хорриотом»; WSDL и схемы публикуются на
   `api.vetrf.ru/schema/platform/services/`.
2. Промышленная эксплуатация API «Хорриот» открыта с 02.03.2024.
3. Доступ предоставляется по официальному письму во ФГБУ «ВНИИЗЖ» с указанием
   программного обеспечения, версии и разработчика.
4. Сначала тестовый контур `t2-aplms.vetrf.ru`, апробация не менее 10 рабочих
   дней, доля ошибок не выше 10% в сутки и отсутствие критических ошибок —
   после этого продуктивный доступ `aplms.vetrf.ru`.

Формальной аккредитации информационных систем нет — это заявочный допуск.
Для плана работ это означает: интеграция с «Хорриотом» реализуема и сроки
предсказуемы, в отличие от ФГИАС ПР.

## 4. Что уже отражено в системе ●

- **GUID животного** — присваивается автоматически, глобально уникален,
  не зависит от номера внутри хозяйства.
- **Проверка формата индивидуального номера** по стандартам Interbull
  (`HOLUS123456789`), США (`HOUSA…`), Канады (`HOCAN…`), Германии
  (`DEHOL` + 7 цифр), РФ (6–15 цифр), плюс контрольная сумма Luhn —
  `src/lib/animal-id.ts`.
- **Транслитерация клички** по ГОСТ 7.79-2000 (ISO-9) в поле `nameLatin`.
- **Справочники НСИ** с сохранением кодов ИАС «Селэкс» (`NPOR`, `NKAT`,
  `NKKLASS`, `NPV`, `NRIP`, `NTIP_SPERM`, `NREZOT`, `NMAST`, `NTEXN`) —
  чтобы миграция данных из «Селэкса» не превратилась в ручное сопоставление.
- **Уровни достоверности данных** — шкала −1…3 с правилом, что племенное
  свидетельство выпускается с уровня 3, а в расчёты запись попадает с уровня 2.
- **Аудит изменений** — `lastEditUser` и `lastEditTime` заполняются автоматически.
