# Модель данных и предметная логика

Описание сущностей, связей, валидаций и правил доступа. Реализовано в коде,
если не указано иное.

Статусы: ● работает · ◐ спроектировано · ○ план.

---

## Граф сущностей ●

```
organizations ──< herds ──< animals >── users (автор записи)
                              │
                              ├──< calvings          отёлы, межотельный цикл
                              ├──< inseminations ──> animals (бык)
                              ├──< milk-tests        контрольные дойки
                              ├──< health-events     здоровье
                              ├──< events            лента событий
                              └──< documents ──> media

organizations ──< data-submissions ──> media (протокол ошибок)

справочники НСИ: breeds, lines, breeding-categories, breeding-classes,
animal-purposes, disposal-reasons, coat-colors, blood-groups,
reproduction-methods, semen-types, insemination-results,
dna-test-types, haplotype-types, health-event-types, technicians
```

## Animal ●

Центральная сущность. Организована вкладками — они же вкладки карточки
в интерфейсе.

| Вкладка | Состав |
| --- | --- |
| **Общие данные** | GUID, индивидуальный номер и его формат, кличка и её латиница, альтернативные идентификаторы (бирка, чип, инвентарный, международный, ISO), пол, тип, состояние, возрастная группа, дата рождения, порода и кровность, масть, назначение, владелец, стадо, автор записи, уровень достоверности, флаги публичности |
| **Оценка** | ИПЦ с прогнозом, достоверностью R,% и процентилем; продуктивные признаки; воспроизводство; здоровье; 18 линейных признаков экстерьера и 3 композита |
| **Фенотип** | сводка для таблицы поиска (удой, жир, белок в % и кг) и массив лактаций |
| **Происхождение** | отец и мать связями, линия и семейство, категория племучёта, класс, текстовая родословная, коэффициент инбридинга |
| **Генетика** | CVM, BLAD, DUMPS, генотипы молочных белков (каппа-казеин, бета-казеин, бета-лактоглобулин), гаплотипы, ДНК-тесты |
| **Движение** | поступление, выбытие с причиной, чипирование, архивация |

### Идентификация

- **GUID** (`uuid`) — присваивается автоматически при создании, глобально
  уникален, неизменяем, не зависит от номера внутри хозяйства. Заготовлен
  под передачу в ФГИАС ПР.
- **Индивидуальный номер** проверяется по формату: Interbull (`HOLUS123456789`),
  США (`HOUSA…`), Канада (`HOCAN…`), Германия (`DEHOL` + 7 цифр), РФ (6–15 цифр),
  внутрихозяйственный. Плюс контрольная сумма Luhn — `src/lib/animal-id.ts`.
- **Транслитерация клички** по ГОСТ 7.79-2000 (ISO-9) в поле `nameLatin`.

### Логические проверки

- потомок не может родиться раньше родителя;
- отец и мать не могут быть одним и тем же животным;
- дата рождения не в будущем;
- инбридинг выше 6,25% — предупреждение, выше 25% — флаг
  «требует ручного подтверждения»;
- `lastEditUser` и `lastEditTime` заполняются автоматически при каждом изменении.

### Чего не хватает для сертификатов ◐

Раздел племенной книги, номер в племенной книге, страна рождения, номер РСН,
способ получения потомка (естественное осеменение / ЭКО / эмбриотрансфер),
селекционер отдельно от владельца. Полный разбор —
[sertifikaty-audit.md](sertifikaty-audit.md).

## Pedigree ●

Родословная строится не отдельной таблицей, а обходом связей `father` / `mother`.

**Дерево на три ряда предков:** О/М → ОО/МО/ОМ/ММ → восемь узлов третьего ряда.
Код узла читается справа налево: ОМ — отец матери, МОО — мать отца отца.
Предки, заведённые карточками, кликабельны; текстовые предки показываются,
но никуда не ведут.

**Коэффициент инбридинга** — формула Райта:

```
F = Σ (1/2)^(p+q+1) · (1 + F_A)
```

Глубина поиска общих предков — 5 поколений (`src/lib/pedigree.ts`).
Если оба родителя связаны карточками, показывается расчёт по дереву;
иначе — значение, пришедшее из импорта. Контрольные значения для проверки:
родитель–потомок 0,5, полные сибсы 0,5, двоюродные 0,125.

### Разметка источников инбридинга

Дерево отвечает на вопрос «откуда взялся инбридинг», а не только «какой он».

| Состояние | Как показано | Что означает |
| --- | --- | --- |
| Общий предок | сплошная заливка своим цветом и точка | встречается и у отца, и у матери — даёт вклад в COI |
| Повтор в одной стороне | пунктирная рамка того же цвета | инбредным является родитель, на инбридинг потомка не влияет |
| Путь к предку | соединители окрашены в цвет группы | видна «петля» инбридинга |
| Не подтверждено | оранжевая точка у кода | у предка уровень достоверности ниже 2 |
| Обрыв ветви | пунктирная серая рамка | предка нет в системе |

Каждой группе повторяющихся предков достаётся свой цвет из палитры вне
фирменной зелёной гаммы — чтобы цвет не читался как «хорошо / плохо».
При наведении на узел подсвечиваются все вхождения того же животного
и пути к ним, остальное дерево приглушается.

**Геномный инбридинг F_ROH** ◐ — см. [genomnyy-konveyer.md](genomnyy-konveyer.md).

## Phenotype Record ●

Фенотип — не одно поле, а четыре потока фактов, каждый со своей датой,
источником и автором.

| Коллекция | Что фиксирует |
| --- | --- |
| `calvings` | номер отёла, дата, результат (тёлка / бычок / двойня / мертворождение / аборт), дойные дни, дата запуска, лёгкость отёла, масса телёнка |
| `inseminations` | дата, бык, тип семени, метод, число доз, номер попытки, техник, результат, дата проверки стельности; привязка к номеру отёла |
| `milk-tests` | дата, номер лактации, суточный удой, жир и белок в %, соматические клетки, лаборатория, источник |
| `health-events` | тип, дата, тяжесть, период, описание, кто зафиксировал, флаг исключения из аналитики |

Разделение принципиально: сводные показатели в карточке — производные,
а первоисточник всегда остаётся отдельной записью с датой. Это то, что
позволяет позже пересчитать оценку по другой методике, не потеряв данные.

## Lactation Curve ●

Лактации хранятся массивом внутри животного. Поля одной лактации:

| Поле | Значение |
| --- | --- |
| `number` | номер лактации |
| `calvingDate` | дата отёла |
| `inseminationDate`, `serviceBull` | осеменение внутри лактации |
| `dd` | дойные дни |
| `milkYield` | удой за лактацию |
| `milk305` | удой за 305 дней |
| `fat305`, `protein305` | жир и белок, % |
| `fatKg`, `proteinKg` | жир и белок, кг |
| `scc` | соматические клетки |
| `dryOffDate`, `endDate` | запуск и окончание лактации |

Сейчас удой за 305 дней принимается из импорта. Правильное поведение ◐ —
считать его самим по контрольным дойкам методом ICAR Test Interval Method
и хранить рядом метод расчёта, чтобы значение было воспроизводимо.

Аппроксимация кривой моделями Wood, Wilmink и Ali-Schaeffer ◐ описана
в [standarty.md](standarty.md).

## Genotype SNP ◐

В коде отсутствует. Спроектированный состав записи:

| Поле | Назначение |
| --- | --- |
| `animal` | связь с карточкой |
| `chip` | модель чипа и число маркеров |
| `assembly` | сборка генома координат |
| `alleleCoding` | конвенция кодирования аллелей исходника |
| `callRate` | доля прочитанных маркеров по образцу |
| `laboratory` | кто выполнил генотипирование |
| `sourceFile` | исходный файл без изменений |
| `qcStatus` | принят / отбракован с причиной |

Сами вызовы по маркерам в реляционной таблице не хранятся — объёмы не те.
Хранилище генотипов отдельное, в модели остаётся ссылка и метаданные.
Подробности — [genomnyy-konveyer.md](genomnyy-konveyer.md).

## Уровни достоверности данных ●

Шкала из технического задания (Таблица №4, поле `NTRUTH`):

| Уровень | Значение | Смысл |
| --- | --- | --- |
| −1 | Отклонено | ошибки или противоречия, в аналитике не учитывается |
| 0 | Черновик | внесено собственником, не проверено |
| 1 | Проверено собственником | требует внешней верификации |
| 2 | Подтверждено лабораторией | проверены ДНК и продуктивность |
| 3 | Верифицировано ассоциацией | можно выпускать свидетельство |

Правило: племенное свидетельство выпускается с уровня 3, в расчёты индексов
запись попадает с уровня 2. Уровень показан в шапке карточки и виден
на всех вкладках; рядом подсказка с полной шкалой.

Не путать с **достоверностью оценки** (шкала 1…5) — та показывает надёжность
прогноза племенной ценности и стоит рядом с таблицами признаков.

## Пакеты загрузки данных ●

Работа Ассоциации с данными хозяйств построена вокруг пакетов
(`data-submissions`).

Жизненный цикл: `uploaded → checking → checked → accepted` (либо `rejected`).
Каждый переход пишется в историю с указанием, кто и когда его совершил.

Карточка пакета показывает статус, дату и время проверки, комментарий
Ассоциации, статистику «обработано / принято / с ошибками» и протокол ошибок
в XLSX. Владелец отмечает согласие с результатом и нажимает «Загрузить данные» —
пакет переходит в `accepted`, животные организации получают уровень
достоверности 3.

**Раздел «История»** в кабинете строится не по пакетам, а по событиям: один
пакет появляется в ленте столько раз, сколько статусов прошёл. Цвет плитки —
состояние шага: оранжевые часы (получен, на проверке), зелёная галочка
(проверен), зелёный флаг (владелец согласовал), красный крест (отклонён).

**Ограничение текущей реализации** ◐: пакет принимается или отклоняется целиком.
Для промышленного объёма нужен построчный приём — часть строк принимается,
часть отклоняется индивидуально с указанием причины.

## Справочники НСИ ●

Справочники живут в базе и редактируются в админке (`/admin`, группа
«Справочники»), а не в коде — требование технического задания.
Минимальный набор полей: код, наименование, описание, порядок сортировки,
признак активности.

Коды сохраняют нумерацию ИАС «Селэкс» (`NPOR`, `NKAT`, `NKKLASS`, `NPV`,
`NRIP`, `NTIP_SPERM`, `NREZOT`, `NMAST`, `NTEXN`), чтобы миграция данных
из «Селэкса» не превратилась в ручное сопоставление тысяч строк.

## Правила доступа ●

| Кто | Что видит |
| --- | --- |
| Аноним | животные с `publicVisible = true`; карточка открывается только при `publicDetails = true` |
| Авторизованный | своя организация полностью плюс чужие публичные записи |
| Администратор Ассоциации | всё |

Владелец управляет флагами в разделе «Личный кабинет → Настройки»;
переключатель применяется сразу ко всему стаду.

## Импорт и экспорт ●

- **Импорт** — «Личный кабинет → Мои животные → Загрузить данные», CSV
  с разделителем `;`. Распознаются колонки: `Инд.№`, `Кличка`, `Пол`,
  `Дата рождения`, `Удой, л`, `Жир, %`, `Белок, %`, `Жир, кг`, `Белок, кг`, `ИПЦ`.
  Существующие животные обновляются по `Инд.№`, чужие записи пропускаются.
- **Экспорт** — `GET /account/export?format=csv|json`, только животные
  своей организации.
