# Показательная книга: что мешает и что нужно

Разбор состояния на 3 сентября 2026 года. Коротко: мешают две вещи,
и они независимы — починив одну, вторую не обойти.

---

## Препятствие первое: запрос не доходит до приложения

`holstein.plem.online/healthz` отвечает, `demo.plem.online` — пустотой.
Пустой ответ не означает «приложение упало»: до приложения запрос
не доходит вовсе.

Домен направлен на сервер — это сделано. Но у платформы, где живёт
приложение, домен ещё должен быть **привязан к самому приложению**
и получить сертификат: сервер отвечает на порт, а какому приложению
отдать запрос, он решает по имени в заголовке. Незнакомое имя даёт
либо пустой ответ, либо чужое приложение.

Проверяется тремя командами:

```
dig +short demo.plem.online
dig +short holstein.plem.online     # должны совпасть
curl -sI https://demo.plem.online   # что отвечает и отвечает ли
curl -sI http://demo.plem.online    # без TLS: если тут ответ есть, дело в сертификате
```

Если адреса совпадают, а по `https` пусто — домен не добавлен в панели
приложения либо для него не выпущен сертификат. Это настройка, а не код.

---

## Препятствие второе, главное: за доменом нет своих данных

Даже когда домен дойдёт, показывать будет нечего — точнее, будет
показано лишнее.

Арендатор (`lib/tenant.ts`) меняет **имя, реквизиты, подписи и правовые
документы**, но не меняет базу. Приложение одно, база одна: открыв
`demo.plem.online`, посетитель увидит двести восемьдесят тысяч настоящих
голштинских животных под словом «демонстрация». Чужие данные, выданные
за примерные, — худшее, что можно сделать с доверием Ассоциации,
которая эти данные нам доверила.

Обойти это внутри одного приложения нельзя, и вот почему. Payload
поднимает подключение один раз на процесс: выбрать другую базу
по заголовку `Host` уже некому — решение принимается до того, как
приходит первый запрос. Отдельная схема в той же базе упирается в то же
самое. Сузить выдачу по арендатору на уровне запросов — это переписать
каждую страницу книги и завести новое место, где право видеть чужое
может разойтись с прежним; недели работы и риск не там, где хочется.

---

## Что нужно сделать

**Второе развёртывание.** То же приложение, своя база, свои переменные:

```
BOOK_HOST=demo.plem.online
SITE_HOSTS=                # витрины здесь нет: это книга, а не витрина
DATABASE_URL=…             # своя база
PAYLOAD_SECRET=…           # свой
```

Пустой `SITE_HOSTS` — законное состояние, и код его понимает: ссылки
из книги на разборы витрины (`SITE_URL`) откатываются на адрес самой книги,
а не собираются в `https://undefined`, как было до правки. Разбор —
в `lib/hosts.ts` рядом с `SITE_URL`.

**Наполнение.** Сид уже написан: `npm run seed:demo` создаёт хозяйство
с семью сотнями животных. Данные придуманные, номера из своего диапазона
(метка 96) — их нельзя спутать с настоящими.

**Переключатель на витрине.** После того как стенд открылся и наполнен,
на витринном развёртывании ставится `DEMO_READY=1`. До этого витрина
на демо не ссылается: страница пород вместо мёртвой ссылки предлагает
разговор.

**Английские экраны.** Показательная книга нужна прежде всего тем, кто
пришёл с английской страницы. Интерфейс книги русский, и до перевода
стенд стоит показывать вместе с экскурсией (`/tour`), а не вместо неё.

---

## Чего делать не нужно

Не заводить демо на общей базе «пока временно». Временное здесь живёт
годами, а цена ошибки — не техническая: один открытый список чужих
животных отменяет разговор о доверии целиком.

Где смотреть: `src/lib/hosts.ts` (`DEMO_READY`, `demoUrl`),
`src/lib/tenant.ts` (арендатор `demo`), `src/scripts/seed-bulk.ts`
(наполнение), `docs/razvertyvanie.md` (как разворачивается приложение).
