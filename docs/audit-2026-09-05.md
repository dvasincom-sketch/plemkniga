Полный проход по `src/collections`, `src/access`, `src/actions`, `src/lib`, `src/app`, `src/components`, `src/scripts`, `src/migrations`, `README.md` и `docs/*.md`. Порядок починки — за вами; ниже находки сгруппированы по тому, кому и чем они вредят, внутри группы — по убыванию цены ошибки.

## A. Права и данные: кто-то получит то, чего не должен

### A1. Через `/api/movements` можно забрать чужое животное себе
`src/collections/Movements.ts:168–189` против `src/actions/movements.ts:147–154`. Действие требует, чтобы записывал владелец; хук коллекции, который по своему же комментарию «защищает прямое обращение к `/api/movements`», проверяет только «`from` или `to` — моя организация». Достаточно быть получателем: `POST /api/movements {animal: X, kind: 'sale', from: <владелец X>, to: <я>}` проходит, `afterChange` переписывает `owner`. Правка перемещений хозяйству закрыта, вернуть корову сможет только Ассоциация. Любой руководитель хозяйства одним запросом делает своей любую карточку книги. Ничем не ловится: `check:security` перемещения не гоняет. Починка — в хуке при `create` требовать `relId(animal.owner) === relId(data.from)` для всех видов, кроме `import`; минуты, перезапуск `next dev`, подтвердить одним POST.

### A2. Пакет данных правит любой вошедший
`src/collections/DataSubmissions.ts:40–43`: `create` и `update` — `isAuthenticated`, хуков принадлежности нет. У заявок на верификацию ту же дыру закрыли (комментарий в `VerificationRequests.ts:69–83` её описывает), у пакетов — нет. `PATCH /api/data-submissions/:id {status: 'checked', review: {…}}` от любого пользователя, после чего `publishSubmissionAction` (`src/actions/submissions.ts:86`) пускает: он проверяет только статус. «Проверено сотрудниками Ассоциации» ставится без Ассоциации, журнал проверок подделывается. Починка — `update: isAssociationAccess`, `create` через `requireOwnOrganization`; минуты.

### A3. Уровень достоверности закрыт на правку, но открыт на создание

По такой записи `issueDocumentAction` выпустит свидетельство. Починка — `create: () => false` на оба поля и POST в `check:security`; минуты.

### A5. Заявку на верификацию через API можно подать в обход условий

### A9. Подтверждение заявки падает: `completeness.ts` читает удалённую колонку

### A10. Коэффициент инбридинга завышен: пути через одного предка считаются дважды
`src/lib/ancestry.ts:88–121, 169–181, 240–262`; тот же приём в SQL подбора `src/lib/mating.ts:209–253`. Обход копит кратности всех предков всех колен, и для общего предка P засчитываются ещё и все предки P — путь «X–S–P–G–P–D–X» проходит через P дважды, что формула Райта запрещает (собственные предки P входят через `(1 + F_P)`). Проверено на бумаге: потомок полных сибсов с известными дедами получает 37,5 % вместо 25 % (P и Q по 0,125 плюс четыре деда по 0,03125); при полной родословной на девять колен «отец × дочь» стремится к 50 % вместо 25 %. Чем полнее родословная, тем сильнее ошибка — наказываются лучшие данные. Число печатается в свидетельстве, сравнивается с введённым в `inbreeding-mismatch` (хозяйство с верным числом получит замечание), в подборе пар помечает безопасные пары как опасные. `check:mating` этого не видит: его семь животных без дедов. Починка — табличный метод либо исключение путей через уже учтённого общего предка, в TS и в SQL; часы; пересчёт хранимого `inbreeding`; расширить `check:mating` дедами; нужен прогон на базе.

### A11. Общие предикаты «отёл» считают отёлом аборт и запуск
`src/lib/sql-herd.ts:68–118` (`calvingsCount`, `lastCalvingDate`, `hasCalved`, `isHeifer` — без условия по `event_type`), `herd-condition.ts:149–153`, `ranking.ts:173–177`, `herd-analytics.ts:789–790`, `cow-evidence.ts:57–62`. Следствия: тёлка с абортом перестаёт быть тёлкой во всех списках молодняка; аборт прибавляет лактацию в структуре стада, выбраковке, рейтинге, подборе; календарь считает «дней после отёла» от запуска. `check:condition` сверяет два расчёта с одной и той же ошибкой. Починка — условие `(event_type is null or = 'calving')` в четырёх предикатах и CTE `calved`; часы с перепроверкой потребителей; прогон на базе с абортами. ### A12. Приём по ICAR ADE: отёлы не записываются, идентификатор ищется по несуществующему полю, бык осеменения выбрасывается

В `push.ts:121–131` заголовок обещает «сперва разбираем всю посылку, потом пишем», разбор идёт в цикле записи — вместе с первым пунктом любой отёл в посылке валит её после записи доений.
