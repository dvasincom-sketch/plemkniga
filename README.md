# Племенная книга — прототип

Информационная система учёта племенной ценности КРС голштинской породы.
Прототип с рабочей логикой: авторизация, ролевой доступ, поиск с фильтрами,
импорт/экспорт данных, карточка животного с оценкой и экстерьером.

## Стек

| Слой | Технология |
| --- | --- |
| Фронтенд | Next.js 16.3 (App Router, Turbopack), React 19.2 |
| Стили | Tailwind CSS v4, шрифт Onest (@fontsource) |
| Бэкенд / CMS | Payload CMS 3.85 (в том же процессе Next.js) |
| БД | PostgreSQL 16 (`@payloadcms/db-postgres`, Drizzle) |
| Деплой | Docker (`output: standalone`), Timeweb Cloud |

## Запуск в Docker

```bash
cp .env.example .env
echo "PAYLOAD_SECRET=$(openssl rand -base64 32)" >> .env
docker compose up -d --build
```

Приложение — на `http://localhost:3000`, база — во внутренней сети Compose
(наружу порт не публикуется). Медиафайлы и данные БД лежат в томах `media` и `pgdata`.

## Деплой на Timeweb Cloud

Есть два рабочих сценария.

### 1. Приложение из Git (рекомендуется)

1. Запушьте репозиторий в GitHub / GitLab.
2. Timeweb Cloud → **Приложения** → *Создать* → тип **Docker**, укажите репозиторий
   и ветку. Dockerfile в корне подхватится автоматически.
3. Timeweb Cloud → **Базы данных** → создайте **PostgreSQL 16**. Скопируйте строку
   подключения; для внешнего подключения добавьте `?sslmode=verify-full`
   (или `?sslmode=require`, если сертификат не устанавливаете).
4. В переменных окружения приложения задайте:

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URI` | строка подключения из панели |
   | `PAYLOAD_SECRET` | `openssl rand -base64 32` |
   | `NEXT_PUBLIC_SERVER_URL` | `https://<ваш-домен>` |
   | `PAYLOAD_DB_PUSH` | `true` при первом запуске, затем `false` |
   | `PORT` | `3000` |

5. Первый деплой создаст схему БД (`push: true`). После этого переключите
   `PAYLOAD_DB_PUSH=false` и работайте через миграции.
6. Домен и бесплатный TLS — в разделе «Домены» приложения.

### Если после деплоя главная отдаёт «A server error occurred»

Откройте `https://<домен>/healthz` — эндпоинт отвечает JSON с состоянием
подключения к базе, списком заданных переменных окружения и подсказками
по типовым ошибкам. Экран ошибки показывает `digest` — по нему запись
находится в логах приложения.

Частые причины:

| Симптом в `/healthz` | Что делать |
| --- | --- |
| `DATABASE_URI: НЕ ЗАДАНА` | добавить переменную в настройках приложения и передеплоить |
| `no pg_hba.conf entry ... SSL off` | добавить `?sslmode=require` в конец `DATABASE_URI` |
| `self signed certificate` | добавить `DATABASE_SSL_REJECT_UNAUTHORIZED=false` |
| `database ... does not exist` | создать базу в панели или указать существующую |
| `relation ... does not exist` | первый запуск сделать с `PAYLOAD_DB_PUSH=true` |
| `ENOTFOUND` / `ECONNREFUSED` | база недоступна из контейнера: проверить хост, порт и сетевые правила |

После успешного деплоя зайдите на `/admin` — Payload предложит создать
первого пользователя-администратора.

## Модель данных

```
organizations ──< herds ──< animals >── users (author)
                              │
                              ├──< calvings
                              ├──< inseminations ──> animals (бык)
                              ├──< milk-tests
                              ├──< health-events
                              ├──< events
                              └──< documents ──> media

organizations ──< data-submissions ──> media (протокол ошибок)

справочники (НСИ): breeds, lines, breeding-categories, breeding-classes,
animal-purposes, disposal-reasons, coat-colors, blood-groups,
reproduction-methods, semen-types, insemination-results,
dna-test-types, haplotype-types, health-event-types, technicians
```

`animals` содержит вкладки:

* **Общие данные** — идентификация, владелец, стадо, флаги публичности;
* **Оценка** — ИПЦ, продуктивные признаки, воспроизводство, здоровье
  (каждый признак = `прогноз` + `R,%`), 18 линейных признаков экстерьера и 3 композита;
* **Фенотип** — сводка для таблицы поиска и массив лактаций;
* **Происхождение** — связи `father` / `mother`, линия и семейство, категория племучёта
  (I — по происхождению, II — по продуктивности), класс, текстовая родословная, инбридинг.
* **Генетика** — CVM / BLAD / DUMPS, генотипы молочных белков, гаплотипы, ДНК-тесты.
* **Движение** — поступление, выбытие с причиной, чипирование, архивация.

### Справочники (НСИ)

ТЗ, Приложение №1 п. 1.2 и требование №20: справочники живут в БД и редактируются
в админке (`/admin`, группа «Справочники»), а не в коде. Минимум полей — код,
наименование, описание; коды сохраняют нумерацию ИАС «Селэкс» (`NPOR`, `NKAT`,
`NKKLASS`, `NPV`, `NRIP`, `NTIP_SPERM`, `NREZOT`, `NMAST`, `NTEXN`), чтобы
упростить будущую миграцию.

### Идентификация и валидация

* **GUID для ФГИАС ПР** (`uuid`) — присваивается автоматически при создании,
  глобально уникален, не зависит от номера внутри хозяйства (ТЗ, п. 7.3).
* **Проверка формата индивидуального номера** по стандартам: Interbull
  (`HOLUS123456789`), США (`HOUSA…`), Канада (`HOCAN…`), Германия (`DEHOL` + 7 цифр),
  РФ (6–15 цифр), плюс контрольная сумма Luhn — `src/lib/animal-id.ts`.
* **Логические проверки родословной**: потомок не может родиться раньше родителя,
  отец и мать не могут быть одним животным, дата рождения не в будущем.
* **Транслитерация клички** по ГОСТ 7.79-2000 (ISO-9) в поле `nameLatin`.
* **Пороги инбридинга**: > 6,25% — предупреждение, > 25% — флаг
  «требует ручного подтверждения».
* **Аудит**: `lastEditUser` и `lastEditTime` заполняются автоматически (ТЗ, п. 1.6).

### Вкладка «События» карточки животного

Оперативное состояние животного четырьмя блоками:

* **Таблица межотельного цикла** — коллекция `calvings`: номер отёла, дата,
  результат (тёлка / бычок / двойня / мертворождение / аборт), количество
  дойных дней, дата запуска.
* **Осеменения** — коллекция `inseminations`, привязка к номеру отёла
  (`id_cow + ld_cow_n_otel`, ТЗ п. 5.2).
* **Продуктивность (лактации)** — массив лактаций с итоговой строкой:
  суммарный удой, средние проценты жира и белка, суммы Ж и Б в кг.
* **Контрольные дойки** — коллекция `milk-tests`; Ж,кг / Б,кг и сумма Б+Ж
  считаются из суточного удоя и процентов.

### Генеалогическое древо и инбридинг

Вкладка «Происхождение» строит дерево на три ряда предков: О/М → ОО/МО/ОМ/ММ →
восемь узлов третьего ряда. Код узла читается справа налево: ОМ — отец матери,
МОО — мать отца отца. Предки, заведённые карточками, кликабельны.

Коэффициент инбридинга считается по **формуле Райта**
F = Σ (1/2)^(p+q+1) · (1 + F_A) — `src/lib/pedigree.ts`, глубина поиска общих
предков 5 поколений. Если оба родителя связаны карточками, показывается расчёт
по дереву; иначе — значение, пришедшее из импорта. Контрольные значения для
тестов: родитель–потомок 0,5, полные сибсы 0,5, двоюродные 0,125.

Рядом с заголовком выводится **уровень достоверности данных** (поле `trustLevel`,
шкала ТЗ Таблицы №4: −1 отклонено, 0 черновик, 1 проверено собственником,
2 подтверждено лабораторией, 3 верифицировано ассоциацией). Ниже — блок
«Источник данных»: ДНК-исследования, пакеты загрузки и документы, из которых
собрана карточка.

### Пакеты загрузки данных

Раздел «События» личного кабинета — это работа с пакетами (`data-submissions`).
Жизненный цикл: `uploaded → checking → checked → accepted` (или `rejected`),
каждый переход пишется в историю с указанием, кто и когда его совершил
(ТЗ, п. 1.6).

Карточка пакета показывает статус, дату и время проверки, комментарий
Ассоциации, статистику «обработано / принято / с ошибками» и **протокол ошибок**
в XLSX для скачивания. Владелец отмечает согласие с результатом и нажимает
«Загрузить данные» — пакет переходит в `accepted`, а животные организации
получают уровень достоверности 3.

### Правила доступа

| Кто | Что видит |
| --- | --- |
| Аноним | животные с `publicVisible = true`; карточка открывается только при `publicDetails = true` |
| Авторизованный | своя организация полностью + чужие публичные записи |
| Администратор | всё |

Владелец управляет этими флагами в **Личный кабинет → Настройки** —
переключатель применяется сразу ко всему стаду.

## Импорт и экспорт

* **Импорт** (`Личный кабинет → Мои животные → Загрузить данные`) — CSV с разделителем `;`.
  Распознаются колонки: `Инд.№`, `Кличка`, `Пол`, `Дата рождения`, `Удой, л`,
  `Жир, %`, `Белок, %`, `Жир, кг`, `Белок, кг`, `ИПЦ`.
  Существующие животные обновляются по `Инд.№`, чужие записи пропускаются.
* **Экспорт** — `GET /account/export?format=csv|json`, только животные своей организации.

## Интерфейсные решения

* **Липкий футер** — `body` растянут на `100dvh` флекс-колонкой, `main` забирает
  свободное место, поэтому подвал прижат к низу даже на коротких страницах.
* **Свои выпадающие списки** — `src/components/Select.tsx` вместо нативного
  `<select>`: роль `listbox`, управление стрелками, Home/End, поиск по первым
  буквам, Esc и клик вне списка закрывают его. Значение уходит в форму скрытым
  input, поэтому компонент работает и в GET-поиске, и в server actions.
  Чекбоксы оформлены классом `.checkbox`.
* **Шапка** — один вход в кабинет (имя пользователя с аватаром) и одна кнопка
  выхода; на странице кабинета дублирующего блока с именем больше нет.
* **Шрифты** — Onest для интерфейса, Unbounded для крупных числовых
  показателей (класс `.stat-value`). Оба подключены из npm, без обращений
  к внешним CDN.

## Что осталось за рамками прототипа

* Расчёт ИПЦ (сейчас значения загружаются извне или генерируются сидом).

* Реальные фотографии — в hero-блоках стоят векторные заглушки

* Почтовый адаптер (подтверждение e-mail, восстановление пароля).
